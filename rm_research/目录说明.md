# 项目目录说明

日常使用时，你只需要关心根目录的 `.env` 和《审核方案.md》。其余目录由研究流程自动读写。

| 目录 | 作用 | 是否需要人工查看 |
|---|---|---|
| `agents/` | 保存研究小组各成员的职责，例如论文研究、开源项目研究、证据审校和报告整理。 | 通常不用 |
| `baseline/` | 保存项目现状、研究模块和检索范围，是后续研究判断“什么值得找”的依据。 | 项目范围变化时查看 |
| `materials/` | 保存用户提供的项目背景、模拟器说明、现有方案等原始材料。 | 补充项目资料时使用 |
| `knowledge/` | 保存全流程共同遵守的长期偏好，例如使用中文、结论可追溯。 | 偏好变化时修改 |
| `queue/` | 每晚检索出的待阅读论文、仓库和跨域资料清单。属于临时工作区。 | 排查当晚检索时查看 |
| `library/` | 已完成核验的证据库和方案账本。`papers/`、`repos/`、`cross/` 分别保存论文、开源项目和跨域证据。 | 核对证据来源时查看 |
| `nights/` | 每晚研究记录，包括处理数量、异常、证据缺口和下一晚建议。 | 想了解某晚做了什么时查看 |
| `proposals/` | 系统内部的方案归并、可行性判断和审校记录，最终会转成根目录的《审核方案.md》。 | 深入追查判断依据时查看 |
| `code/` | 人工采纳方案后生成的实施任务书和验收用例；系统不会直接修改正式工程。 | 采纳方案后查看 |
| `logs/` | 运行日志、阶段校验结果、每晚统计和断点恢复状态。 | 运行失败或核对工作量时查看 |
| `skills/` | 保存研究小组的专用工作方法。当前包含“范围锁定、英文优先、宁缺毋滥”的文献地图检索方法。 | 通常不用 |
| `systemd/` | 每晚自动启动所需的系统定时器模板。 | 通常不用 |
| `tools/` | 检索、正文读取、证据保存、文件保护、模型切换和夜间控制工具。 | 通常不用 |
| `tests/` | 自动检查证据账本、文件保护、谷时限制等规则是否正常。 | 修改流程后用于验证 |
| `.venv/` | 项目独立运行环境和依赖。体积较大，但运行必需。 | 不要手工修改或删除 |

## 根目录主要文件

| 文件 | 作用 |
|---|---|
| `.env` | 唯一的模型、夜间时间、工作量和自动恢复配置文件。 |
| `审核方案.md` | 唯一的人工审核入口；勾选“采纳”后才能生成实施计划。 |
| `run.sh` | 手动启动基线研究、夜间研究或实施规划。 |
| `install-nightly-service.sh` | 安装或重新安装每晚自动启动功能。 |
| `crew.*.jsonc` | 四个阶段的工作流程定义。 |
| `llms.py` | 统一读取 `.env` 中的主模型、备用模型和审校模型。 |
| `README.md` | 面向使用者的操作说明。 |
| `pyproject.toml`、`uv.lock` | 项目依赖清单和锁定版本，保证不同时间运行结果尽量一致。 |

## 哪些目录会不断增长

- `library/`：积累经过核验的长期证据，不应自动删除。
- `nights/`：积累每晚研究记录。
- `logs/`：积累运行日志；旧日志可以定期清理，但每晚总结和运行统计建议保留。
- `queue/`：临时候选清单，确认对应夜间任务完成后可以清理旧文件。
