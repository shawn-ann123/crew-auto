# RM 打符 + 自瞄研究小组

这个项目会持续收集打符与装甲板自瞄相关资料，把它们整理成带证据的改进方案，经你审核后再生成实施和验收计划。

完整目录用途见《[目录说明.md](目录说明.md)》。日常使用只需要编辑 `.env` 和《审核方案.md》，其余目录由系统维护。

## 你需要关心的文件

### 1. `.env`

唯一的模型配置文件。在这里填写模型名、模型地址和 API Key。

首次使用时：

```bash
cp .env.example .env
```

然后只编辑 `.env`。主模型必填；备用模型和独立审校模型可选。

### 2. `审核方案.md`

唯一的人工审核文件。每个方案会说明：

- 要解决的问题；
- 建议做什么；
- 预期收益与风险；
- 证据强度；
- 论文、开源项目或其他资料的具体来源；
- 反对意见和判断是否值得做的方法。

方案不会写编程接口、算法参数或具体实现步骤。决定采纳时，只需把：

```markdown
- [ ] 采纳
```

改成：

```markdown
- [x] 采纳
```

## 工作流程

1. **建立基线**  
   系统先理解现有项目、打符与自瞄的范围，形成稳定的研究分类。这一步通常只做一次。

2. **夜间研究**  
   系统找新论文、开源项目和可借鉴的其他领域方法，排除重复资料，并区分「已读正文」「仅摘要」和「仅项目介绍」。

3. **整理方案**  
   新证据会与已有证据合并。系统评估收益、代价、风险和反对意见，然后把值得你决策的内容追加到《审核方案.md》。

4. **人工审核**  
   你阅读方案、核对来源，然后决定是否勾选采纳。系统不会自动替你采纳方案。

5. **实施与验收规划**  
   只有已勾选的方案会被转换成实施任务和可复现的验收计划。证据较弱的方案只会先安排小规模验证。

## 日常使用

首次建立基线：

```bash
./run.sh baseline
```

运行一晚研究，研究完后打开《审核方案.md》：

```bash
./run.sh nightly
```

`nightly` 只会在 DeepSeek 谷时运行。默认每晚处理 2 篇论文、1 个开源项目和 1 篇跨域资料，最长运行 6 小时；这些标准都可以在 `.env` 修改。

首次启用每晚自动启动：

```bash
./install-nightly-service.sh
```

电脑在夜间开机时，系统会在 `.env` 指定的窗口自动启动。断网、模型暂时不可用或进程崩溃时会自动重试；已经校验完成的阶段不会重复执行。每晚完成后的实际资料数、方案数和是否达标记录在 `logs/nightly-summary-日期.json`。

勾选方案后，生成实施和验收计划：

```bash
./run.sh code
```

需要立即停止后续新任务时，在项目根目录创建一个名为 `STOP` 的空文件。删除它后可恢复。
